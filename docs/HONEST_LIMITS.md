# HONEST LIMITS — quotable text for the README (security-architect)

1. The kit is a **drift and accident detector, not a sandbox**: built for a cooperative-but-sloppy worker, not for an adversary with a shell.
2. It **guarantees** that every edit is compared against a hash recorded earlier, that the test floor can only rise through the CLI, and that a rewritten ledger prefix, a lowered floor or a deleted state file is reported.
3. It **only detects** — it cannot prevent a write; whatever a process with file access can rewrite, it can rewrite. The kit makes that LOUD (hash, tripwire, ledger), never impossible.
4. It **cannot stop** a worker that edits `tools/aw.py` (a judge can always lie about itself), one that deletes `baseline.json`, `ledger.json` *and* `baseline.log` together, a secret that matches no pattern, or an injected instruction a model chooses to obey.
5. A PASS is a claim until the architect re-runs the gate; if a worker can type `--i-am-architect`, it can re-baseline its own drift — the flag guards against accidents, not intent.
6. **Habit 1 — commit before the worker starts.** VCS is the only witness that survives a rewritten engine; `git status` and `git diff` catch what no hash inside `.aw/` can.
7. **Habit 2 — read `.aw/baseline.log`.** Every baseline and every raise is one dated line; an unexplained line is a finding, whatever the other files say.
8. **Habit 3 — re-audit on a fresh clone or a second machine.** `gate` + `integrity` + `audit` there is the only check the worker never touched.
9. Records the kit cannot repair stay records: keep the last accepted state in git and prefer "restore from `backups/<T-NNN>`" over "fix forward".
10. Everything printed is MEASURED or UNMEASURED — treat UNMEASURED as "not checked", never as "fine", and report a drift before explaining it.
11. Smaller is stronger: a card that names its files, a check that does not import the code it audits, one command per step — these beat any amount of policy text.
12. The kit never deletes your data and never overwrites on install; if you need more than that, you need a separate account or container, not a patch.
13. **`card-lint` is a subset of `docs/CARD_LINT_RULES.md`.** Measured on 2.0.1 against the 39 deliberately broken reference cards: it catches 23, misses 16 (rules L09, L18 for one-digit numbers, L31, L32, L33 in INVARIANTS, L34, L36, L37, L39, L40 count variant, L41-L46). `CARD-LINT OK` means the checked structure holds, not that the card is correct; the DRY-RUN PROOF and the runtime `audit` stay the real checks.
14. **Effort is applied at launch, not inside a chat (2.8.0).** Hermes has no tool with which a running chat sets its own reasoning level, and it does not tell the model its level, so `tools/effort.py` can only be obeyed where the kit starts the session (`START_ARCHITECT.cmd`, `START_WORKER.cmd`); in a chat opened any other way the Architect prints one line and the Author picks the level. `ultra` is sent as `max` on the two current routes (claude-sonnet-5-5, deepseek-v4.1-flash). The cost of ultra against medium is MEASURED only for the cheap worker (12 pilots: median reasoning tokens 2,049 against 3,952 = 1.9x, output tokens 8,994 against 11,822 = 1.3x, wall time not separable: medians 282 and 284 s, ranges 144-403 and 205-369; 5 of 6 queues passed at medium, 6 of 6 at ultra, p=1.0) and UNMEASURED for the Architect model; the W3 size limits sit above all 19 cards seen so far and no failure has yet shown what predicts one.
15. **A green `selftest.py` does not prove the engine unchanged (2.8.2).** `dev/mutation_probe.py` changes one token of `payload/tools/aw.py` per mutant (`==` to `!=`, `and` to `or`, a dropped `not`, an integer + 1) and runs the suite. MEASURED on 2.8.1, two samples with no shared site (200 + 120 of 1,041 sites): 178 of 320 mutants turned the suite red (56%), 142 left it green. The 26 checks added in 2.8.2 kill 37 of the 77 survivors they were written from that still exist and 6 of the 59 of the independent sample (48% against 10%): there 53 of 118 one-token changes still pass, between 4 and 5 of every 10 (the 59 killed before were not run again). Some survivors are equivalent (a number inside a message, a default that is never used) and were not counted apart. UNMEASURED: every other kit file (`effort.py`, `learn.py`, the installers), other kinds of change (a deleted statement, a changed string), Linux and macOS.
16. **A suite written from survivors fits the sample it was written from (2.8.3).** 2.8.3 adds 84 checks (189 -> 273) from the mutants that survived. MEASURED by replay: the seven other kit files, all 365 sites, 241 -> 343 killed (94%), but those mutants are the ones the checks came from. The independent sample of `payload/tools/aw.py` (seed 3, 120 mutants, no site used by any check): 74 killed before, 75 after, so the real kill rate of `aw.py` against a new one-token change is about 62%, while the samples the checks were written from read 81% and 84%. 18 survivors of the seven files were called equivalent by the worker and not checked one by one. UNMEASURED: other kinds of change, an independent sample of the seven smaller files, Linux and macOS.
17. **Where the mutation numbers stop (2.8.4).** MEASURED: on a fresh independent sample of `payload/tools/aw.py` (seed 4, 120 one-token mutants, drawn before any check of 2.8.4 was written) 65% were killed by the 2.8.3 suite and 71% by the 299 checks of 2.8.4; the samples the checks were written from read 81% to 91% and say little about a new change. The seven other kit files: 348 of 365 mutants killed (95%), the rest judged not observable by reading the source, not proven. Python: `selftest.py` passes in full on 3.10.21 and does not load on 3.9.25; the installed engine ran `doctor`, `integrity` and `report` the same on both; the requirement written in the README stays 3.11+. UNMEASURED: Linux and macOS (the exec-bit check runs only there), other kinds of change, and the 7 `aw.py` survivors called equivalent.
18. **The harvest proposes, it does not prove (2.9.0).** `dev/harvest.py PROJECT...` runs each project's own `tools/learn.py` read-only and prints its candidates with `project:file:line`, plus the PROPOSED rows and the feedback topics; a family met in 2 or more projects is `cross_project`. It uses the same keyword families as `learn.py`: it tells you where to look, not what is true. A K-NN row in `dev/KIT_PROPOSALS.md` becomes VERIFIED only with a selftest check or card-lint rule that is RED on the previous kit. It does not run `aw.py improve` (that prints counts, not citations). UNMEASURED: whether a barrier lowers the hit count of its family (that needs a census of the PROPOSED rows in the live projects), Linux and macOS.
